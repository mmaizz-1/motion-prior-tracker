## 这次完成了什么

项目已从依赖鸟类场景的处理脚本，整理为“给定首帧目标框，持续输出目标状态”的通用单目标组件。类别编号、初始化框、搜索参数、运动模型和文件输出可以分别配置。通用化指接口不依赖鸟类，并不代表已经验证任意物体上的跟踪精度。

核心入口仍是 `motion_prior_tracker.py`，已有 `process_folder()` 调用和 YOLO 标签格式继续保留。新增模块按职责拆分，同时在原入口导出公共类型：

| 模块 | 作用 |
|---|---|
| `tracking_types.py` | `TargetSpec`、`TrackerConfig`、`TrackObservation` 与输入验证 |
| `motion_prior_tracker.py` | 初始化、逐帧更新、连续序列跟踪、状态输出 |
| `template_matching.py` | OpenCV 模板搜索、尺度搜索、图像裁剪 |
| `motion_models.py` | 匀速、Kalman、恒加速度三种可替换运动先验 |
| `sequence_io.py` | 自然顺序逐帧读取、标签与统计保存、源文件保护 |
| `tracking_cli.py` | 单序列/多序列运行、参数配置和 JSONL 汇总 |
| `examples/embodied_attention.py` | 消费观测状态并产生注意/搜索提示 |
| `examples/synthetic_demo.py` | 可重复生成的非鸟类目标对照实验 |

每帧返回归一化目标框、像素中心、像素/帧速度、外观匹配分数、类别、连续丢失帧数及状态。状态分为 `ref`（给定首帧框）、`matched`（匹配）、`predicted`（仅运动预测）、`recovered`（丢失后重新匹配）。预测帧的 `measurement_valid=false`、`score=0`，便于下游区别观测与推断。

## 审查中修复的问题

1. **恒加速度状态更新。** 连续无测量帧同时推进位置和速度；重新获得测量时，按真实测量之间的间隔估计加速度，不把预测位置当作真实观测。对于位置序列 0→1→3，下一帧预测为 6。模型接口提供可读速度，返回数组副本避免外部修改内部状态。
2. **目标消失后匹配到背景。** 仅带 padding 的模板分数可能被周围背景主导。现在同时验证上下文、目标模板与未加 padding 的目标内容，并提高默认目标阈值；弱匹配不刷新模板。纯黑目标采用严格的亮度误差判定，避免零能量归一化错误。
3. **目标变大时搜索区域不足。** 搜索范围同时考虑最大允许尺度在四个方向的占用，避免候选模板被搜索窗口截断。
4. **状态与边界语义。** 显示框完整限制在图像内，`center_px` 与显示框一致；内部运动状态可在画面外，`velocity_px` 保留模型意义。已初始化的 `track_sequence()` 会处理传入的每一帧。
5. **目录与命令行一致性。** 默认继承首帧标签类别，显式参数才覆盖。图像按数字自然顺序逐帧解码，支持中文路径。拒绝重名输出、源文件覆盖、非法标签与参数；多序列 telemetry 汇总重复运行时替换，不重复追加。

初始化目标的宽和高都需至少 3 像素。小于此范围的目标直接报错。这是明确的支持边界，不能通过放宽阈值宣称解决不可观测问题。

两个序列各 28 帧，图像 400×240，目标约 24 像素；索引 12–15 隐藏目标，16 重新出现。六次运行均在 12–15 输出预测，在 16 输出恢复。所有索引从 0 开始。

### 真实鸟类片段

从原始序列 16 复制了 12 帧进行运行检查，文件名从 `000461.jpg` 到 `000516.jpg`，图像 3840×2160。只使用首帧参考框，没有使用独立的逐帧真值。

最终默认配置输出：**3 帧被接受（包含首帧初始化），9 帧纯预测，0 次恢复**。本机该次运行约 5.24 秒、2.29 帧/秒；这只是该设备和该样本上的处理速度。统计中的 `match_rate=0.25` 是程序接受状态的比例，不是跟踪准确率。

早期宽松匹配会把草地接受为目标；最终版本更倾向于标记丢失，减少错误观测继续污染模板。当前结果也说明真实鸟类片段上的持续跟踪能力仍需提高，不能据此声称精度提升或实际部署已就绪。

## 与具身智能的具体连接

这项工作的定位是**视觉感知层到上层策略之间的目标状态组件**。机器人或移动相机先给出关注目标框，跟踪器逐帧提供位置、图像速度与观测有效性，上层再选择持续观察、短暂保持或主动寻找。

已有可调用的 `attention_hint(observation)` 示例：有效且分数不低于 0.5 时输出 `observe` 及归一化图像中心误差；低分观测或短时丢失输出 `hold`；连续丢失超过 3 帧输出 `search`。这些输出为策略提示，不是机器人执行指令。

当前没有自动发现目标、多目标身份关联、在线检测器融合、深度、三维世界坐标或机器人闭环。移动相机会改变图像速度，接入实际任务还需相机运动补偿和标定。面向研究，建议先用逐帧真值比较“无先验/匀速/Kalman/恒加速度”的遮挡后恢复时间、中心误差和 IoU，再接入目标跟随任务评估闭环成功率。现有接口和示例为这条路径提供可运行起点，不构成完整具身智能系统或独立的创新性证明。

## 复现方法

在源码目录创建独立 Python 3.11 环境后：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python examples/synthetic_demo.py --output demo_out
python motion_prior_tracker.py --input demo_out/sequences --output demo_cli --model ConstantVelocity --telemetry demo_cli/tracks.jsonl
```

输入图像目录的首张图像旁需有同名 `.txt`，格式为一行 `class_id cx cy width height`，坐标归一化。程序支持单个序列目录或多序列父目录。详见 README 中的 API、状态协议与参数说明。
